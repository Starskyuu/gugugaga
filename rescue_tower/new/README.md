# 智能城市救援塔 · 树莓派总控（一键网页版）

> 本文件夹 `new/` 是**新增**的，原有文件一个都没动。
> 整条流程：**水位传感 → 树莓派 → 升降台升起 → 人工放船 → 找人 → 无人船自动救人**

## 文件清单

| 文件 | 作用 |
|---|---|
| `救援总控.py` | 主程序：状态机 + 自动导航 + 一键网页（全中文注释，只用标准库） |
| `config.py` | **集中配置**：IP、阈值、速度，以后只改这里 |
| `start.sh` | 一键启动脚本 |
| `测试/mock_hardware.py` | 离线闭环测试：假硬件跑通整条链路（上真机前先跑它） |

## 部署到树莓派（整体目录保持不动）

树莓派上已经跑通过 `rescue_tower`，只需要把 `new/` 整个拷到 `rescue_tower/` 里：

```bash
# 电脑上（或直接把文件夹拖过去）把 new 拷到树莓派的 rescue_tower 目录里
# 最终结构：
#   rescue_tower/
#   ├── esp32/           （固件，不动）
#   ├── raspberry_pi/    （666.py、best.pt、标定，不动）
#   └── new/             （本目录）
```

## 使用

### 1. 一键启动（正式运行）

```bash
cd rescue_tower/new
bash start.sh
```

总控会自动：监听水位板 TCP → 探测视觉 → **没在跑就自动启动 666.py**。
手机/电脑浏览器打开 `http://<树莓派IP>:8080`（树莓派 IP 用 `hostname -I` 看）。

### 2. 网页操作

| 按钮 | 什么时候用 |
|---|---|
| ▶ 一键开始 | 不想等水位传感器，直接演练整条流程 |
| 船已放好，开始找 | 升台后人工把船放到水面，点一下立即开始（不点也行，摄像头看到船 3 秒自动开始） |
| ■ 急停 | 任何时候，小船立即停 |
| 复位，再救一轮 | 完成/急停后回到待命 |

网页上还有：实时俯视图（船▲、人●、目标◎）、水位/坐标/距离、摄像头画面、事件日志、手动调试按钮（船前后左右停、升降台升降）。

### 3. 电脑上离线演示（不连任何硬件）

```bash
cd rescue_tower/new
python 救援总控.py --demo
```

自动开网页 `http://127.0.0.1:8080`，模拟水位 2.5 秒后报警，模拟船自己找模拟人。**上真机前先跑这个确认程序本身没问题。**

## 真机前必做：离线闭环测试

```bash
cd rescue_tower/new
python 测试/mock_hardware.py
```

用假硬件走一遍真实网络协议（HTTP/TCP/UDP 和真机完全一样），
自动断言：水位触发 → 升台 `/U` → 看到船 → 找到人 → 自动航行 → 停船到达。
**退出码 0 才算通过；失败说明程序有 bug，先别上真机。**

## 单模块调试（逐块确认硬件）

```bash
python3 救援总控.py --check-water --live   # 持续看水位读数，用手摸传感器看变化
python3 救援总控.py --check-vision --live  # 持续看船/人坐标（666.py 需已启动）
python3 救援总控.py --lift U --live        # 升降台升起
python3 救援总控.py --lift D --live        # 升降台降下
python3 救援总控.py --boat F 1 --live      # 小船前进 1 秒
python3 救援总控.py --boat L 0.5 --live    # 小船左转 0.5 秒
python3 救援总控.py --boat S --live        # 小船停车
```

不带 `--live` 只打印模拟动作，不会真动设备。

## 真机检查清单（按顺序）

1. 手机开热点 Mate 70 Pro，三块 ESP32 上电，串口确认 IP
2. `config.py` 填 `BOAT_IP`、`LIFT_IP`（水位板不用填，它自己连树莓派 5000 口）
3. 确认船上 ArUco 编号 = `config.BOAT_ID`
4. 先跑 `--check-water --live`：干燥时记下读数，用手摸/沾水看读数变化，
   把 `WATER_DELTA_TRIGGER` 改成"浸水读数 - 干燥读数"的一半左右
5. 先跑 `--check-vision --live`：确认船和人都能识别出坐标
6. 架空船体（螺旋桨离水/离地），逐个跑 `--boat F/L/R/S --live`，
   确认方向对。**方向反了改 `config.TURN_SIGN = -1`**
7. `--lift U` 时掐表，把 `LIFT_UP_TIME_SEC` 改成实际升起时间
8. 全部通过后 `bash start.sh`，网页里看俯视图和日志

## 常见问题

| 现象 | 处理 |
|---|---|
| 网页打不开 | 确认和树莓派同一 WiFi（Mate 70 Pro）；`hostname -I` 看 IP；网页端口在 config 里是 8080 |
| 网页显示"未就绪（标定/参考点问题）" | 666.py 没识别够 5 个场地参考 ArUco，检查摄像头视野和灯光 |
| 水位一直显示"—" | 水位板没连上：它的固件里写死了树莓派 IP `192.168.43.12`，确认树莓派就是这个 IP |
| 船一直原地转 | 船头朝向装反/ArUco 贴歪，改 `config.BOAT_ID` 对应的 `BOAT_HEADING_OFFSETS_DEG`（在 666.py 里），或改 `TURN_SIGN` |
| 端口被占 | 队友的视觉服务 6.py 也用 8080，不要同时开两个；`lsof -i:8080` 看是谁 |
| 想开机自动启动 | 树莓派上执行 `crontab -e` 加一行：`@reboot sleep 20 && cd /home/pi/rescue_tower/new && bash start.sh >> logs/总控.log 2>&1` |

## 安全设计（为什么敢让船自己跑）

- 小船固件 700ms 收不到命令**自动停车**；总控每 0.2s 发一次命令续命
- 视觉数据掉线/过期 → **立即停车**，等恢复
- 靠近目标 150mm 内自动**半速**，防止冲撞
- 网页急停按钮随时可用；Ctrl+C 退出也会先发停车
- 连续 5 次视觉异常自动触发急停保护
