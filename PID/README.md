# 城市方舟 —— PID 视觉导航（树莓派 + ESP32）

## 系统结构

```
[树莓派: 视觉识别 + 双环PID]  --WiFi HTTP /M?A=..&B=..-->  [ESP32-C3: 电机驱动]  -->  DRV8833  -->  左/右空心杯电机
        ^                                                                          (差速转向)
        └────────── 摄像头（定位船、识别目标、算航向） ──────────┘
```

双环 PID：
- **外环（速度）**：到目标的剩余距离 → 总油门（越远越快，接近自动减速）
- **内环（航向）**：目标方位与当前航向的误差 → 差速转向量
- **混合**：左电机 = 油门 + 转向，右电机 = 油门 − 转向

## 文件

| 文件 | 作用 | 运行位置 |
|---|---|---|
| `esp32_main.py` | 原网页遥控程序 + 新增 `/M` 连续油门接口 | ESP32-C3（Thonny 刷写） |
| `nav_control.py` | 纯 PID 控制算法（PID 类、Navigator、参数） | 树莓派 + 电脑仿真共用 |
| `pi_pid_nav.py` | 视觉导航主程序：读视觉 → PID → 下发 ESP32 | 树莓派 |
| `sim_test.py` | 船模运动学仿真，下水前调参用 | 电脑 |

## 第一步：刷 ESP32

用 Thonny 打开 `esp32_main.py`，另存到板子上为 `main.py`，重启。
网页遥控功能完全不变；新增改动都标了【新增】/【修改】注释：

1. 新增接口 `GET /M?A=40&B=-35`（A/B 为左右电机油门，-100..100）
2. 自动模式下关闭 500ms 起步加速（否则 PID 微调会变成满功率抽搐）
3. `/M` 命令超时 1000ms 自动停车（手动命令仍为 700ms）

## 第二步：树莓派联网

树莓派连上手机热点（`Mate 70 Pro` / `87654321`，和 ESP32 同一个网络）：

```bash
sudo nmcli device wifi connect "Mate 70 Pro" password 87654321
```

运行主程序（纯标准库，无需 pip 安装任何东西）：

```bash
python3 pi_pid_nav.py
```

`ESP32_IP` 留 `None` 会自动扫描整个网段找 ESP32；扫描失败就把 Thonny
里打印的 `ESP32 IP` 填进去。手机热点分配的 IP 偶尔会变，变了自己改一下。

## 第三步：实现视觉接口（唯一必须自己写的部分）

在 `pi_pid_nav.py` 里实现 `VisionInterface.get_state()`，返回
`(boat_x, boat_y, heading, target_x, target_y)`。三条硬性约定：

1. **非阻塞**：在另一个线程里跑视觉识别、持续更新最新结果，`get_state()`
   只把最新值交出来；**没有新结果返回 None**（程序会停车，绝不带着旧数据瞎开）。
2. **同一坐标系**：位置和航向必须用同一个坐标系，0° 指向 +x、向 +y 为正
   （与 `atan2` 一致）。直接用图像像素坐标也可以——航向用两帧位移
   `atan2(dy, dx)` 或船头-船尾连线算，天然满足约定。**不要混用罗盘北角。**
3. **单位统一**：用像素就全用像素，用米就全用米；`NavConfig` 里的
   `accept_radius`、`slow_zone`、`kp_s` 跟着统一。

建议把像素坐标标定到世界坐标（米），控制更稳、参数更好理解。例：

```python
import cv2, numpy as np
world = np.float32([[0, 0], [10, 0], [10, 5], [0, 5]])      # 4个点的实际坐标(米)
pix   = np.float32([[100, 600], [900, 620], [940, 120], [120, 140]])  # 对应像素
H, _  = cv2.findHomography(pix, world)
def to_world(px, py):
    p = H @ np.array([px, py, 1.0])
    return p[0] / p[2], p[1] / p[2]    # 船头点也这样变换后再 atan2 算航向
```

## 第四步：先在电脑上仿真调参（下水前必做）

```bash
python sim_test.py          # 可选：pip install matplotlib 看图
```

目标：`结果：arrived`，且轨迹不绕圈、不蛇形。调参顺序：

| 现象 | 调整 |
|---|---|
| 转向太肉 / 转不过去 | 加大 `kp_h` |
| 船头左右蛇形摆动 | 减小 `kp_h`（或加一点 `kd_h`） |
| 远处跑得慢 | 加大 `kp_s` |
| 快到目标冲过头、绕圈 | 加大 `kd_s` / 减小 `kp_s` |
| 半路停住不动（实际船） | 加大 `min_cruise`（电机死区补偿） |
| 到点不停、来回晃 | 加大 `accept_radius` / `kd_s` |
| 转向方向反了 | `turn_sign = -1` |

调好后把同一组参数填进 `nav_control.py` 的 `NavConfig` 默认值。

## 第五步：下水实测

1. 岸上干跑：船拿在手上，程序跑起来，看终端打印的 A/B 油门是否随
   船-目标相对位置合理变化。
2. 下水先从近距离小目标开始，`accept_radius` 建议 ≥ 2 倍船长。
3. 手动网页和自动导航是**后到先得**：测试自动导航时别碰手机按钮。

## 安全链（三层兜底）

1. 视觉拿不到新数据 → 树莓派主动发停车
2. 树莓派死机 / 断网 → ESP32 一秒收不到 `/M` 自动停车
3. Ctrl+C 退出程序 → 停车

## 常见问题

- **ESP32 收不到命令**：确认树莓派和 ESP32 在同一个热点；IP 是否填对。
- **船原地转圈不走**：`min_cruise` 不够大，或摄像头坐标系 y 轴反了
  （此时航向定义也会反，先查约定再查参数）。
- **到目标附近绕圈**：`kp_h` 太大或 `accept_radius` 太小。
