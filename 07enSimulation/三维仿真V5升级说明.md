## 二、物理引擎（BoatPhysics.cs）

基于 Unity PhysX 刚体（`Rigidbody`，mass=0.030 kg，continuous dynamic，14 次求解迭代）：

1. **浮力（Archimedes）**：船底 4 个采样点，浸没深度 × 浮力系数 → 升力；
2. **扶正力矩**：依据横摇/纵摇角施加恢复力矩（类似稳心高），保证船不会翻；
3. **推进**：油门 → 螺旋桨推力（世界系 + 船头方向）；
4. **舵效**：舵角 → 偏航力矩（仅在有前进速度时有效，符合真实船性）；
5. **阻力**：纵向阻力（船速越大阻力越大，自然限速）+ 横向阻尼（防侧滑）；
6. **软边界**：场地半宽 0.26 m 处的弹性墙，替代原来的硬夹紧；
7. **限速**：`ClampSpeed` 防止物理积分发散；
8. **尾迹**：船速超阈值时粒子系统喷泡沫（程序化生成的泡沫纹理）。

## 三、自动驾驶（BoatController.cs）

- 保留原有航点跟随 + 右舷避碰逻辑，但输出改为 **油门/舵角指令** 写入 BoatPhysics，不再直接改 `transform`；
- 航向误差 → 舵角（rudderGain=2.1）；需要掉头时挂倒挡 kick 辅助转弯；
- 航线绘制（DrawRoute）沿水面高度绘制（`WaterSystem.HeightAt`），波浪上也能看见航迹。

## 四、水面波浪（WaterSystem + RescueWater.shader）

- 双 Gerstner 波叠加：主波（波长 14 cm，波速 0.30 m/s）+ 次波（波长 5.5 cm，波速 0.55 m/s）；
- **关键设计**：着色器里的 `WaveHeight()` 与 `WaterSystem.HeightAt()` 波参数逐字同步——渲染的浪高 = 浮力计算的浪高，船不会"插进水里"或"悬空"；
- 视觉：解析法线、浪尖泡沫、Blinn-Phong 太阳高光、掠射角加深、URP 雾。

## 五、模型美化（ProceduralRescueModels.cs）

- **船体**：由原来的胶囊体改为 5 站线型船体网格（25 顶点 / 46 三角面，绕序已离线验证并翻转到外法线），带水线、甲板条、防擦条；
- **部件**：驾驶舱顶、雷达桅 + 桅灯、左右红绿舷灯 + 白色尾灯（自发光）、舷外机罩 ×2、螺旋桨 ×2、艉栏杆、救生圈（圆环）、天线；
- **基站**：浮筒、防撞垫、门、信标灯（BeaconFlasher 呼吸闪烁自发光）、旗杆 + 三角旗、天线 ×2、雷达碟；
- **落水人员**：带救生圈（圆环），随波起伏。

## 六、场景自动重建机制

- `RescueSceneGenerator` 使用 `[InitializeOnLoadMethod]` + `EditorPrefs` 记录 `VisualVersion`；
- 打开 Unity 时检测到当前为 v4（比旧版大）会**自动重建整个场景**，无需手动操作；
- 若想强制重建：菜单 `Edit → Preferences → 删除 RescueVisualVersion` 键，或直接改版本号。

## 八、联调注意事项

1. **UDP 协议不变**：Unity 仍发 `VISION_FRAME`（9200 端口）、收 `ROUTE_PLAN`（9300 端口），Python 规划器无需任何改动；
2. **坐标系不变**：规划用 2D X-Y（cm），Unity 用 X-Z（cm），场地 0.60 m；
3. 首次打开项目时若水面显示品红，等 2 秒（着色器导入重试）或右键 RescueWater.shader → Reimport；

## 十、V5 修复与建模迭代（2026-09-05）

### 修复：船无法出港

物理化之后船会与基站发生碰撞，而旧出生点恰好位于基站几何体内。修复分三层：

1. **SafetyZone 视觉地标**删除碰撞体（纯视觉元素）；
2. **基站主碰撞体**改为 `isTrigger = true`（几何码头不再构成物理墙）；
3. **船出生点**从基站内部移到四个角落 `(18,18) (18,42) (42,18) (42,42)` cm——物理船体出生时不再与任何碰撞体交叠。

### 美化：基站建模（60+ 部件）

浮筒裙边+浮筒端盖、角护舷、甲板铺板条+橙色安全边带、系缆柱+羊角、周边栏杆（立柱×14+横杆×4）、正面悬挂救生圈、舷梯、指挥舱基座+两级台阶、四面窗+后门+窗竖梃、橙色屋顶+金属檐口、屋顶栏杆+立柱、太阳能板×4、贯通式雷达塔+斜撑+雷达碟+馈源、信标底座+呼吸信标灯、双天线、旗杆+旗+旗顶球、码头灯柱×2。

### 美化：小人建模

浮圈前后绳结、救生衣前后板+衣领圆环+肩带+哨子、头发、左右手、左臂高举招手（求救姿态）、右臂外展保持平衡。

### 程序化圆环（新增）

Unity `PrimitiveType` **没有 Torus**。新增 `CreateTorusMesh(outerRadius, tubeRadius, segments, tubeSegments)` 在 XY 平面朝 +Z 生成圆环网格（24×8 段），配 `MeshPart` 辅助函数挂载自定义网格（无碰撞体，性能更优）。用于：船尾救生圈、人员浮圈、救生衣衣领、基站栏杆救生圈。

## 十一、V6 修复：船打转、无法抵达落水人员（2026-09-05）

### 根因 1：舵效力矩量级错误（致命）

`rudderTorqueScale` 原值 `0.00085`，而船体偏航转动惯量仅 ~`1.6e-5 kg·m²`（0.030 kg 质量 + 厘米级箱体碰撞体）。角加速度高达 ~2100 rad/s²，**船在到达第一个航点前自转了约 66 圈**。修正为 `0.0000004`（4e-7），并新增垂荡阻尼 `heaveDamping=0.6`。

### 根因 2：航点极限环（纯追踪 + 速度下限）

修正舵效后仍不收敛：纯追踪控制配合速度下限会形成绕航点的**稳定圆形轨道**（观测：半径 2.3 cm、恒定 74° 航向误差、54°/s 偏航率），永远进不了 1.5 cm 容差圈。且**大前瞻会抄近道跳过中间航点**，顺序消费模式下被跳过的航点永久卡死路线（船在落水者 0.6 cm 外永远打转）。

全部修复均在**离线 Python 仿真**（`tmp/route_search2.py`，逐项复刻 BoatPhysics/BoatController 的数学）中验证后才写回 C#：

| 修复 | 内容 |
|---|---|
| 误差缩放速度 | 航向误差大时目标速度按 `cruise × max(0.03, 1-|err|/40)` 收缩（低速地板 0.03 打破圆形轨道） |
| PD 舵 | `rudder = clamp(2.1·err − 1.2·yawRate, ±40°)`（新增 D 项，`BoatPhysics.YawRateDeg`） |
| 距离前瞻 | 沿路线取 ≥9 cm 处的航点（与规划器航点间距解耦） |
| 窗口航点消费 | 顺序消费 + 8 航点窗口内最远命中消费，切角跳点不再卡死路线 |
| 低速舵效保底 | `rudderSpeedFloor=0.25`（原 `Clamp01` 在低速时舵效归零，无法原地转向） |
| 取消倒挡掉头 | 倒挡时舵向反转是失控源；改为纯前进 + 低速原地转向 |
| 容差放宽 | `waypointTolerance` 0.6 cm → 1.5 cm（仍小于救援半径 2.5 cm，能稳定触发营救） |

**离线验证**：18 组参数在 1 cm / 3 cm 两种航点密度路线全部收敛（9~21 s），最终选型 `LD=0.09, gain=1/40, esf=0.03, df=0.002, tol=0.015, kp=2.1, kd=1.2`。真实规划器输出为 A*（0.1 m 网格）+ `simplify_path` 后的**拐点路线**（换算到 Unity 世界约 1~3 cm 航点间距），恰在验证范围内。

### 配套修改

- `BoatController.cs`：新增 `rudderDampGain / lookaheadDistance / headingErrSpeedGain / headingErrSpeedFloor / distanceSpeedFloor` 字段；`FixedUpdate` 重写为 PD + 误差缩放速度 + 窗口消费 + 距离前瞻；
- `BoatPhysics.cs`：新增 `YawRateDeg` 属性、`rudderSpeedFloor` 舵效保底；
- `RescueSceneGenerator.cs`：`VisualVersion` 5 → 6，打开 Unity 自动重建场景（新参数以脚本默认值生效）。
