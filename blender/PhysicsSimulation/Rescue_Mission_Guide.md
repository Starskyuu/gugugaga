# Step 6 — Single Boat Rescue Mission

## 观看

打开 `06_Rescue_Mission.blend`，场景选择 `SIM_06_Rescue_Mission`。默认停在第1帧，鼠标放在时间轴按空格播放；Shift＋左方向键回到开头。

演示约80秒，60 fps，共4823帧。相机会自动切换全景、接人近景、爬梯和安置长凳。时间轴有英文阶段标记，可以直接跳转。材质预览的播放速度取决于电脑性能，不一定达到实时60 fps。

| 时间（约） | 内容 |
| --- | --- |
| 0–3秒 | 北侧双扇舱门开启，船保持系泊 |
| 3–12秒 | 双桨推进，空载船浮着驶出北侧船库 |
| 12–22秒 | 接人平台系泊，放下踏板、打开船头护栏，两人依次登船就座 |
| 22–31秒 | 两人随船返航，双桨反转，船头朝外倒车进入原泊位 |
| 31–41秒 | 基地系泊、下船，两人依次离开船体，解除各自载荷 |
| 41–75秒 | 沿平台和橙色梯子登上甲板，在避雨棚下的长凳就座 |
| 75–80秒 | 基地舱门关闭，任务完成 |

## 物理部分

- 保持船体70×50 mm、基地约280×280 mm、小人约21.7 mm高，不是实船尺度。
- 船体延续六自由度重力、浮力、阻力、双桨推进和转向计算，航行轨迹不是手画的位置关键帧。
- 采用平静水面和北侧直线路径；返航使用负转速倒车，避免在狭窄船库里转身。其他三艘船静态待命，第6步没有调度四船。
- 每位模型小人暂估1 g；依次就座时总质量为12→13→14 g，下船时14→13→12 g。
- 加入和移除载荷时重新计算重心及完整惯量矩阵，并同步修正浮力采样点、桨作用点相对重心的位置。保持船体几何位置连续，不因更换重心而瞬移。
- 当前参数下，直立静水平衡吃水为空载4.568 mm、两人载荷5.234 mm。实际运动中还存在纵倾，因此这两个数值不是每一时刻的实测吃水。
- 北泊位侧壁、后壁及滑门有简化水平矩形接触代理和法向冲量响应。它不是对整座基地进行任意网格碰撞求解。
- 停泊时用理想约束固定平面位置和艏向，但不锁定升沉、横摇、纵摇，登船后的吃水和倾斜仍由浮力求解。

## 人物动作和模型调整

人物行走、爬梯、坐下、船头护栏和舱门开合均为编排动作，不是布娃娃、足底接触或安全带受力仿真。站坐过渡期间不逐帧计算脚步和人体移动对船的反作用；载荷在完成就座时加入，到达固定转移平台时移除，采用缓慢、同速转移近似。坐定后人物跟随船体姿态，安全带为贴合外观和固定座位约束示意。

原基地的底板和门槛会挡住浮船，所以**只在06号工程副本**降低船库底板、底座、下裙边和门槛，底板上表面设为水面下12 mm；加了平台延伸、可收起踏板，以及新船头开口护栏。原船、基地和人物源文件，以及04、05号工程均未覆盖。

## 验证与范围

`Rescue_Mission_Validation_Report.json`：19项检查通过，包括载荷/惯量恢复、无任务碰撞、关闭舱门阻挡强制驶出、地板余隙、靠泊误差、倒车转速，以及半时间步长对照。半步长与默认计算的阶段结束时间最大差约1.04 ms。默认过程中最大横摇/纵摇约2.17度，保守底板余隙约5.37 mm。

`Rescue_Mission_Geometry_Report.json`：8项几何/动画数据检查通过，包括模型尺度、两个人物、四张原长凳、载人时姿态跟随、最终就座及关门。不是全模型网格穿插或足底接触验证。

这些结果是当前估算参数的功能与数值检查，**不是经过实物测量校准的工程结论**。不包含波浪、表面张力、CFD、基地升降、实时遥控、柔性安全带、人物接触动力学或四船协同。原设计的地下升降仍是背景设定。

## 文件与重新计算

- `Rescue_Mission_Parameters.json`：任务路径、阶段时长、两位乘员的质量/重心/惯量估计及座位位置。
- `Rescue_Mission_Results.json`：逐帧船体原点、重心位置、姿态、质量、惯量、RPM、阶段、舱门比例、乘员名单以及上下船事件。
- `../scripts/06_Rescue_Mission_Physics.py`：重新计算物理任务，生成结果和13项基础检查。
- `../scripts/06_Validate_Rescue_Mission.py`：补充关闭门测试、惯量和时间步长检查，生成19项检查报告。
- `../scripts/06_Build_Rescue_Mission.py`：在打开05号工程的干净Blender会话中运行，建立06号工程并调用最终检查脚本。重复构建前重新打开05号工程，先保存自己需要保留的编辑。
- `../scripts/06_Finalize_And_Check_Mission.py`：修正最终座位匹配、补充安全带和照明、检查动画数据并保存06号工程。

物理脚本可在带NumPy的Python或Blender Python中执行。已有06号工程的播放是烘焙结果，不会因为修改JSON自动更新；重算后还需重建动画。当前人物路线和北泊位几何固定；若改接人点、基地、乘员数量、座位或基础重心，必须同步调整构建脚本和通行检查，不能只改JSON就视作适配完成。
