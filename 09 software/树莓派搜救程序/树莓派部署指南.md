# 树莓派搜救路线计算程序部署指南

## 1. 适用架构

程序运行在 Raspberry Pi 5（4 GB 足够）上。视觉传感模块把小船与人的相对坐标通过 UDP 发送到树莓派；树莓派计算路线后，为每艘船输出一个 UDP 路线包。核心程序只使用 Python 标准库，不需要联网安装算法依赖。

```text
视觉模块 --UDP 9200--> 树莓派路线服务 --UDP 9300--> 船端网关/控制器
                                      └--> runtime/last_plan.json
```

## 2. 复制与安装

推荐 Raspberry Pi OS 64-bit Bookworm 或更新版本，Python 3.10 以上。

只需将整个 `树莓派搜救程序` 文件夹复制到树莓派，例如 `/home/pi/树莓派搜救程序`，然后执行：

```bash
cd /home/pi/树莓派搜救程序
chmod +x install.sh
./install.sh
```

安装脚本会把程序放入 `/opt/rescue-planner`，配置放入 `/etc/rescue-planner/config.json`，并建立开机服务。它不会覆盖已经存在的配置。

编辑配置：

```bash
sudo nano /etc/rescue-planner/config.json
```

启动并查看日志：

```bash
sudo systemctl start rescue-planner
sudo systemctl status rescue-planner
journalctl -u rescue-planner -f
```

后续更新程序时再次运行 `./install.sh`，然后执行：

```bash
sudo systemctl restart rescue-planner
```

## 3. 坐标和场地配置

默认输入单位为厘米，原点位于场地左下角，+X 向右，+Y 向上。默认场地为 60×60 cm，中央基站范围为 `[19, 22.5, 41, 37.5]`，即宽22 cm、高15 cm；障碍安全余量为2.5 cm。

每条船配置包含安全航速和出坞点：

```json
"boat_1": {"speed": 8.0, "launch": [15.4, 27.0]}
```

`speed` 单位跟随 `coordinate_unit`，默认是 cm/s。实际部署前必须用尺测量场地和出坞点并替换示例值。

## 4. 视觉输入协议

视觉模块向树莓派的 UDP `9200` 发送 UTF-8 JSON：

```json
{
  "type": "VISION_FRAME",
  "timestamp": 1788400000.12,
  "boats": [
    {"id": "boat_1", "x": 22.5, "y": 27.0},
    {"id": "boat_2", "x": 22.5, "y": 33.0},
    {"id": "boat_3", "x": 37.5, "y": 27.0},
    {"id": "boat_4", "x": 37.5, "y": 33.0}
  ],
  "people": [
    {"id": "person_1", "x": 7.0, "y": 8.0},
    {"id": "person_2", "x": 52.0, "y": 49.0}
  ]
}
```

注意事项：

- 船 ID 必须与配置一致。
- 同一个人必须在连续帧中保持相同 ID。
- 坐标必须已经完成像素到场地坐标的标定。
- 人不能位于中央基站安全区或场地外。
- `people` 也可以命名为 `victims`；坐标字段也兼容 `x_cm/y_cm`。
- 坐标或目标集合发生变化时自动重新规划；完全相同的帧不会重复计算。

## 5. 路线输出协议

默认向 `127.0.0.1:9300` 输出，每艘船一包：

```json
{
  "type": "ROUTE_PLAN",
  "version": 1,
  "algorithm": "exact_dp_astar",
  "coordinate_unit": "cm",
  "boat_id": "boat_1",
  "victim_ids": ["person_1", "person_3"],
  "targets": [
    {"id": "person_1", "x": 8.0, "y": 10.0},
    {"id": "person_3", "x": 12.0, "y": 48.0}
  ],
  "waypoints": [{"x": 22.5, "y": 27.0}, {"x": 15.4, "y": 27.0}],
  "distance": 35.2,
  "estimated_time_s": 6.4
}
```

将 `route_output.host` 改为船端网关的 IP，或在树莓派上运行自己的控制程序监听 `9300`。每条路线都带递增 `version`，船端应拒绝旧版本。

`targets` 是本船按访问顺序负责的人员；`waypoints` 是包含绕开基站安全区所需拐点的完整航迹。船控应依次跟踪 `waypoints`，到达对应目标坐标后执行救援动作。若视觉帧中的人员列表为空，程序会向四船下发 `algorithm: "idle"` 的空任务。

## 6. 算法自动选择

- 目标数 ≤ 12：精确四船子集动态规划 + Held–Karp访问顺序 + A*栅格避障。
- 目标数 > 12：均衡最近邻任务分配 + 矩形可见图避障，支持最多1000个固定目标。

配置中的 `planning.algorithm` 可设为 `auto`、`exact` 或 `balanced`。精确算法保证当前离散模型与目标函数下的最优结果，但人数增长时计算量呈指数上升；均衡算法适合大量目标，但不保证全局最优。

## 7. 上机前自检

先开三个终端。

终端1，监听输出：

```bash
cd /opt/rescue-planner
python3 route_receiver_example.py
```

终端2，手动运行服务：

```bash
cd /opt/rescue-planner
python3 pi_rescue_service.py --config /etc/rescue-planner/config.json
```

终端3，发送样例坐标：

```bash
cd /opt/rescue-planner
python3 vision_input_example.py
```

终端1应收到4个 `ROUTE_PLAN` 数据包；服务日志应显示算法名称、目标数量和规划耗时。完整汇总同时保存在 `/opt/rescue-planner/runtime/last_plan.json`。

## 8. 接入真实视觉代码

视觉代码完成检测与单应性变换后，只需把每帧结果组装成上述字典并发送：

```python
payload = json.dumps(frame).encode("utf-8")
udp_socket.sendto(payload, ("127.0.0.1", 9200))
```

如果视觉模块与树莓派不在同一设备，将目标地址改成树莓派局域网 IP，并在防火墙/路由器中允许 UDP 9200。

## 9. 安全边界

本程序输出的是全局航点，不应直接把坐标当作PWM值。船端仍需进行航向闭环、限速、失联停机和人工急停。正式联调顺序应为：记录坐标回放、无桨台架、单船低速、双船、最后四船。当前大规模算法未实现严格的时空预约避碰，因此多船同时靠近同一狭窄区域时必须保留安全间距和人工监控。
