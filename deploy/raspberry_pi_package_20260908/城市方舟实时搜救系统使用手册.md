# 城市方舟实时搜救系统使用手册

版本：1.0  
适用目录：`F:\gugugaga`

本手册用于在 Windows 电脑或树莓派 5 上启动视觉识别服务、打开搜救控制前端，并在保留 ESP32 安全停车机制的前提下完成实时联调。

> 安全原则：ESP32 上的松手停车、700ms 无命令停车和 Wi-Fi 断开停车必须始终保留。视觉画面卡顿、坐标异常或网络中断时，应立即停止船体。

## 1 系统组成

系统由三个部分组成：

```text
手机或电脑浏览器
        │
        │ 前端页面 视频 状态 控制
        ▼
电脑或树莓派视觉服务
        ├─ USB摄像头
        ├─ YOLO人员识别
        ├─ ArUco船体定位
        ├─ 场地坐标换算
        └─ ESP32控制转发
                    │
                    ▼
               ESP32船体
```

### 1.1 主要文件

| 部分 | 文件或目录 | 作用 |
|---|---|---|
| 船体控制 | `run/main.py` | ESP32-C3 电机控制和安全停车 |
| 视觉服务 | `run/6.py` | 摄像头、YOLO、ArUco、坐标和网页接口 |
| 识别模型 | `run/best.pt` | 人员检测模型，类别为 `person` |
| 摄像头标定 | `run/camera_calibration_usb.json` | 镜头内参和畸变参数 |
| 控制前端 | `frontend/` | 实时画面、状态、方向控制和事件记录 |

### 1.2 默认端口

| 端口 | 服务 | 用途 |
|---|---|---|
| `3000` | 前端开发服务 | 浏览器控制界面 |
| `8080` | 视觉服务 | 状态、视频和控制桥接接口 |
| `80` | ESP32 HTTP 服务 | 原始 `F/B/L/R/S` 控制接口 |

## 2 电脑端树莓派功能复制

电脑可以临时代替树莓派运行摄像头、YOLO、ArUco 和实时接口。复制的是软件功能链路，不代表电脑与树莓派 ARM 环境的性能完全相同。

### 2.1 已安装环境

当前电脑已经安装并验证：

- Python 3.13
- OpenCV 5.0
- OpenCV ArUco 模块
- Ultralytics
- PyTorch 和 Torchvision
- `best.pt` 模型可以正常加载
- 0 号摄像头可以正常读取

模型信息：

```text
任务：detect
类别：person
```

### 2.2 安装命令

如果以后更换 Python 环境，需要重新安装依赖：

```powershell
python -m pip install opencv-contrib-python ultralytics
```

验证 OpenCV 和 ArUco：

```powershell
python -c "import cv2; print(cv2.__version__); print(hasattr(cv2, 'aruco'))"
```

正常结果中，ArUco 应显示：

```text
True
```

## 3 快速启动

系统需要两个终端窗口：一个运行视觉服务，一个运行前端。

### 3.1 启动视觉服务

打开 PowerShell：

```powershell
cd F:\gugugaga\run
python 6.py --no-display --host 127.0.0.1 --port 8080
```

看到以下信息说明视觉服务已启动：

```text
YOLO model loaded.
Web API: http://127.0.0.1:8080
Video : http://127.0.0.1:8080/video
```

如果需要显示原始 OpenCV 窗口，可以去掉 `--no-display`：

```powershell
python 6.py --host 127.0.0.1 --port 8080
```

本地窗口中按 `Q` 退出。无窗口模式在终端按 `Ctrl+C` 退出。

### 3.2 启动前端

另开一个 PowerShell：

```powershell
cd F:\gugugaga\frontend
npm run dev
```

浏览器打开：

```text
http://localhost:3000
```

注意：

- `http://localhost:3000` 是控制前端。
- `http://localhost:8080` 是视觉和控制接口，不是前端页面。
- `http://localhost:8080/video` 是 MJPEG 实时视频。
- `http://localhost:8080/api/status` 是实时 JSON 状态。

### 3.3 前端连接地址

电脑本机运行时，前端中的“树莓派服务地址”填写：

```text
http://localhost:8080
```

当前前端在本机 3000 端口打开时，会自动尝试连接该地址。

## 4 前端操作

### 4.1 状态区域

前端能够显示：

- 视觉服务是否在线
- 视觉数据更新时间
- 摄像头 FPS
- YOLO 推理 FPS
- 可见 ArUco 参考点数量
- 已定位船只数量
- 已定位人员数量
- 控制请求延迟和事件记录

### 4.2 方向控制

| 动作 | 页面操作 | 键盘 | ESP32 命令 |
|---|---|---|---|
| 前进 | 按住前进 | `W` 或向上键 | `F` |
| 后退 | 按住后退 | `S` 或向下键 | `B` |
| 左转 | 按住左转 | `A` 或向左键 | `L` |
| 右转 | 按住右转 | `D` 或向右键 | `R` |
| 紧急停车 | 红色 STOP 或顶部急停 | 空格键 | `S` |

方向按钮采用“按住运动，松手停车”。按住期间每 200ms 重新发送一次运动指令。

以下情况也会发送停车命令：

- 触控事件被系统取消
- 浏览器进入后台
- 手机锁屏
- 窗口失去焦点
- 操作者按下空格键

### 4.3 任务视野

视觉服务在线时，任务视野显示树莓派或电脑提供的 MJPEG 标注画面。

画面中可能包含：

- YOLO 人员检测框
- 人员置信度
- 人员场地坐标
- ArUco 标记
- 船只坐标
- 船体朝向箭头
- 摄像头和 YOLO 性能数据

## 5 连接真实 ESP32

电脑或树莓派需要与 ESP32 处于同一个 Wi-Fi 或手机热点中。

### 5.1 获取 ESP32 地址

启动 `main.py` 后，在 ESP32 串口输出中找到：

```text
ESP32 IP:
192.168.x.x
```

不要把热点密码写入公开文档或代码仓库。

### 5.2 启动控制桥接

假设 ESP32 地址为 `192.168.43.120`：

```powershell
cd F:\gugugaga\run
python 6.py --no-display --host 127.0.0.1 --port 8080 --esp32-url http://192.168.43.120
```

地址末尾不要添加 `/F`、`/S` 等命令路径。

### 5.3 推荐启动顺序

1. 抬离水面或架空船体，避免首次联调时意外运动。
2. 启动 ESP32 并确认 `HTTP SERVER READY` 和设备 IP。
3. 启动电脑或树莓派视觉服务，并配置 ESP32 地址。
4. 启动前端并确认视觉服务在线。
5. 短按方向按钮测试，每次测试后确认电机停止。
6. 验证松手停车、700ms 超时停车和断网停车。
7. 所有保护通过后再下水测试。

### 5.4 ESP32 安全机制

| 保护 | 触发条件 | 预期结果 |
|---|---|---|
| 松手停车 | 方向按钮或方向键释放 | 前端立即发送 `S` |
| 心跳超时 | 超过 700ms 未收到运动命令 | 两侧电机停止 |
| Wi-Fi 断开 | ESP32 检测到无线连接丢失 | 停车并尝试重连 |
| 页面失焦 | 切后台、锁屏或窗口失去焦点 | 前端发送 `S` |
| 程序退出 | ESP32 程序进入 `finally` | 电机停止并关闭服务 |

## 6 视觉识别和场地坐标

### 6.1 ArUco 编号

| 编号 | 用途 | 输出 |
|---|---|---|
| 0 至 5 | 船体标记 | 船 ID、X、Y 和角度 |
| 6 至 13 | 场地参考点 | 建立像素到场地坐标的单应性 |

当前参考坐标范围为 0 至 200，单位配置为 `mm`。参考点 ID 10 已统一为：

```text
(100, 100)
```

如果实际场地不是 200mm 见方，应测量真实坐标并修改 `REFERENCE_POINTS`，不能只在前端进行视觉缩放。

### 6.2 人员识别

`best.pt` 当前只有 `person` 类别。程序使用检测框底边中心作为人员与场地平面的接触点，再通过单应性转换为场地坐标。

默认置信度阈值：

```text
0.50
```

### 6.3 坐标准备状态

只有在可见参考点足够且单应性计算成功时：

```json
"coordinate_ready": true
```

参考点不足时，YOLO 仍可绘制人员检测框，但无法可靠输出人员和船只的场地坐标。

## 7 摄像头标定

现有标定文件信息：

```text
分辨率：1280×720
样本数：15
RMS重投影误差：约1.061
```

当前电脑摄像头实际约为 640×480@30FPS，没有接受程序请求的 1280×720@60FPS。程序会按比例缩放相机内参，但使用目标摄像头和目标分辨率重新标定通常更可靠。

### 7.1 启动标定

```powershell
cd F:\gugugaga\run
python 6.py --calibrate
```

### 7.2 标定操作

1. 改变标定板与摄像头的距离。
2. 改变标定板俯仰角。
3. 让标定板分布到画面中间和四周。
4. 按空格采集一组数据。
5. 建议采集至少 15 组不同姿态。
6. 按 `C` 计算并保存标定结果。
7. 按 `Q` 或 `Esc` 退出。

不要对完全静止的标定板连续采集多张几乎相同的图像。

## 8 局域网远程访问

`localhost` 永远表示正在打开网页的那台设备。手机访问 `localhost` 时会连接手机自己，而不是电脑。

### 8.1 开放视觉服务

```powershell
python 6.py --no-display --host 0.0.0.0 --port 8080 --esp32-url http://ESP32的IP
```

### 8.2 开放前端

```powershell
cd F:\gugugaga\frontend
npm run dev -- --host 0.0.0.0
```

### 8.3 手机访问

1. 手机与电脑连接同一个 Wi-Fi 或手机热点。
2. 在电脑执行 `ipconfig`。
3. 找到当前无线网卡的 IPv4 地址。
4. 假设电脑地址为 `192.168.43.10`，手机打开：

```text
http://192.168.43.10:3000
```

5. 前端中的视觉服务地址填写：

```text
http://192.168.43.10:8080
```

6. 如果连接被拒绝，在 Windows 防火墙中允许 Python、Node.js 或相应端口。

### 8.4 公网限制

当前系统没有以下能力：

- 用户登录和身份认证
- HTTPS 加密
- 控制权限管理
- 单操作者锁
- 公网安全中继

因此不要直接进行路由器端口映射，也不要直接暴露到公网。跨城市或跨网络控制前，需要先补齐上述安全能力。

## 9 接口说明

### 9.1 接口列表

| 方法和路径 | 用途 | 返回内容 |
|---|---|---|
| `GET /api/status` | 完整系统快照 | JSON |
| `GET /api/vision` | 第一版视觉快照 | JSON |
| `GET /video` | MJPEG 标注视频 | multipart 视频流 |
| `GET /video.mjpg` | MJPEG 标注视频 | multipart 视频流 |
| `GET /F` | 前进 | `F` |
| `GET /B` | 后退 | `B` |
| `GET /L` | 左转 | `L` |
| `GET /R` | 右转 | `R` |
| `GET /S` | 停止 | `S` |
| `GET /api/control?command=F` | JSON 控制接口 | JSON |
| `POST /api/control` | JSON 控制接口 | JSON |

POST 请求示例：

```json
{
  "command": "F"
}
```

### 9.2 状态字段

| 字段 | 含义 |
|---|---|
| `coordinate_ready` | 是否已建立场地坐标 |
| `boats` | 船只 ID、X、Y 和角度 |
| `persons` | 人员坐标和置信度 |
| `performance` | 摄像头、显示和 YOLO 性能 |
| `references` | 可见参考点、内点和 ID |
| `age_ms` | 距离最近一次视觉更新的毫秒数 |
| `control` | ESP32 配置、最近命令、延迟和错误 |

没有配置 ESP32 地址时，视觉接口仍然可以使用，但控制接口会返回：

```text
HTTP 503
ESP32 URL 未配置
```

这是预期的安全行为。

## 10 常见故障

### 10.1 ERR CONNECTION REFUSED

原因：目标端口没有程序监听，通常是服务没有启动或已经被关闭。

处理：

```powershell
# 检查前端
http://localhost:3000

# 检查视觉接口
http://localhost:8080/api/status
```

重新启动对应服务后刷新页面。

### 10.2 Hydration failed

原因：服务器首屏和浏览器首屏文字不一致，或者浏览器仍在使用旧前端资源。

当前代码已经修正初始化时间导致的水合问题。使用以下快捷键强制刷新：

```text
Ctrl + Shift + R
```

### 10.3 视觉服务无响应

检查：

- `6.py` 终端是否仍在运行
- 地址是否为 `http://localhost:8080`
- 端口是否被其他程序占用
- 防火墙是否拦截连接
- `/api/status` 是否能够直接打开

### 10.4 摄像头画面空白

可能原因：

- 摄像头正被微信、会议软件或系统相机占用
- 摄像头编号不是 0
- 浏览器无法访问 `/video`
- 摄像头权限被系统关闭

尝试使用其他编号：

```powershell
python 6.py --camera 1 --no-display --host 127.0.0.1 --port 8080
```

### 10.5 找不到 best.pt

确保文件位于：

```text
F:\gugugaga\run\best.pt
```

程序会优先使用 `best_ncnn_model` 文件夹，不存在时才使用 `best.pt`。

### 10.6 缺少 ultralytics

错误：

```text
ModuleNotFoundError: No module named 'ultralytics'
```

安装：

```powershell
python -m pip install ultralytics
```

### 10.7 缺少 cv2 或 ArUco

安装带 ArUco 的版本：

```powershell
python -m pip install opencv-contrib-python
```

### 10.8 参考点不足

如果 `references.visible` 少于 4：

- 调整摄像头位置
- 增大或重新打印 ArUco 码
- 改善光照
- 避免反光和遮挡
- 确认字典与程序一致

### 10.9 坐标明显变形

检查：

- 现场 ArUco ID 是否贴错
- `REFERENCE_POINTS` 是否与真实位置一致
- ID 10 是否为 `(100,100)`
- 摄像头标定文件是否对应当前摄像头
- 摄像头是否在运行过程中发生移动

### 10.10 控制返回 503

说明视觉服务没有配置 ESP32，或者 ESP32 地址不可达。

使用：

```powershell
python 6.py --no-display --esp32-url http://ESP32的IP
```

## 11 安全操作

### 11.1 每次启动前

- [ ] 螺旋桨周围无人、无缠绕物
- [ ] 电机方向与前端方向一致
- [ ] 红色 STOP 可以停车
- [ ] 空格键可以停车
- [ ] 松手后电机立即停止
- [ ] 700ms 超时保护有效
- [ ] Wi-Fi 断开后电机停止
- [ ] 视觉数据持续更新
- [ ] ArUco 参考点数量足够
- [ ] 只有一名操作者控制船体

### 11.2 运行中

- 画面冻结时立即停车。
- 延迟升高时立即停车。
- 坐标明显跳变时不要继续自动导航。
- 不要仅依据 YOLO 结果判断人员真实位置，应结合实时画面确认。
- 不得绕过 ESP32 的 700ms 超时保护。
- 避免多个浏览器同时操作方向按钮。

### 11.3 正常关机

1. 单击紧急停车。
2. 确认电机完全停止。
3. 关闭或断开船体电机电源。
4. 在视觉服务终端按 `Ctrl+C`。
5. 在前端终端按 `Ctrl+C`。
6. 确认摄像头指示灯关闭。

## 12 联调检查表

| 检查项目 | 通过标准 |
|---|---|
| ESP32 在线 | 能收到单字符命令确认 |
| 安全停车 | 松手、切后台和超时均能停车 |
| 视觉接口 | `/api/status` 持续返回且 `age_ms` 较小 |
| 摄像头 | 实时画面连续，无明显旧帧积压 |
| YOLO | 能识别 `person` 并输出置信度 |
| ArUco | 参考点不少于 4 且 `coordinate_ready` 为 `true` |
| 船体坐标 | 位置和朝向与现场一致 |
| 局域网 | 手机可以访问前端和视觉接口 |
| 控制权限 | 没有第二个页面同时发送控制命令 |
